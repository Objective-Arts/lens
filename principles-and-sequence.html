Claude-Optimal

Principles & Setup Sequence

I

Core Principles

1

Claude knows. It just doesn't apply.

Without explicit requirements, Claude optimizes for "works" not "expert-quality"

2

Expert > Knowledge

Generic vs expert code isn't what you know—it's whose perspective you apply

3

Build it in, don't bolt it on

Quality is generative (shaped from the start) not corrective (fixed after)

4

Four levers: Experts, Rules, Gates, Triggers

Canon (whose perspective) + Standards (what good looks like) + Flags (quality checkpoints) + Auto-invoke (automatic activation)

II

Setup Sequence

1
Apply a Profile
Pick your experts
Profiles bundle the experts relevant to your stack. A React project needs Dan Abramov; a Java project needs Joshua Bloch. This loads the right perspectives so Claude thinks through expert eyes.
Command
cc-config profile apply javascript+react -p /path/to/project
Or manually symlink skills to .claude/skills/
2
Add Standards to CLAUDE.md
Set the rules
Standards make rules explicit: 30-line max functions, single responsibility, framework-specific patterns. Without these, Claude uses its own judgment. With them, Claude treats quality as a requirement.
Action
Copy from docs/FRAMEWORK-TEMPLATES.md to project CLAUDE.md
Include universal rules + your framework's idioms + anti-patterns
3
Add Auto-Invoke Rules
Wire the triggers
Auto-invoke rules activate experts based on context: React code triggers Dan Abramov, auth code triggers Bruce Schneier. You don't have to remember who to invoke—the system does it for you.
Add to CLAUDE.md
| React components | INVOKE /abramov | | Auth code | INVOKE /schneier then /owasp |
Copy the full table from docs/PROFILES.md
4
Use Flags in Requests
Add the gates
Flags trigger specific quality gates: plan before implementing, test after coding, review before presenting. They turn quality from hope into process.
Examples
Build the dashboard --structure-first --test all --doc-code --review-hard
--structure-first (plan) | --test (tests) | --doc-code (docs) | --review-hard (review)
5
Verify with /status
Check your work
The /status command shows what's loaded: which canon masters are active, which agents are available, what standards apply. Use it to confirm your setup is correct.
Command
/status
Shows: Canon stack, Standards, Agents, Auto-invoke rules

Result

Claude now writes code through expert lenses, following explicit standards, with quality gates enforced at every step.

"The question that unlocks everything: Who has solved this before, and better than I could?"
