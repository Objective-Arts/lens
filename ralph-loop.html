Ralph Loop — Canon-Driven Development

Every step invokes specific canon masters. The canon IS the methodology.

1
Read PRD Item
/procida
WHY: Diátaxis framework ensures requirements are structured correctly—tutorials vs. how-tos vs. reference. Prevents misunderstanding what type of work this is.
2
Load Context
/feathers
WHY: "Working Effectively with Legacy Code"—understand existing code before changing it. Seams, characterization tests, dependency breaking.
/petroski
WHY: "Form follows failure"—check git history for what broke before. Past failures teach more than past successes.
3
Implement
Base Brain (Always)
/kernighan
WHY: "Clarity is better than cleverness"—write code humans can read. K&R style, meaningful names, simple control flow.
/pike
WHY: Data dominates. Simple interfaces. "When in doubt, leave it out." Minimalism in API design.
/linus
WHY: "Bad programmers worry about code, good programmers worry about data structures." Design data first, code follows.
Language Masters (Per Stack)
Java: /bloch — Effective Java patterns, builder pattern, immutability, API design
C#: /skeet + /toub — LINQ, async/await, modern C# idioms
JavaScript: /crockford + /simpson — Good Parts, closures, "this" binding
React: /abramov — Hooks, composition, mental models
TypeScript: /vanderkam — Type narrowing, inference, structural typing
Go: /pike — Proverbs, simplicity, interfaces
Python: /hettinger — Pythonic idioms, descriptors
UI/UX (If Frontend)
/frost + /ive + /norman
WHY: Atomic Design structure. Visual minimalism. Affordances and feedback. The UI canon ensures components are correct before code review.
4
Self-Review
/dijkstra
WHY: "Testing shows presence of bugs, not absence." Correctness by construction—think formally about invariants and preconditions.
/schneier
WHY: "Think like an attacker." Security mindset—what could an adversary do with this code? Threat modeling.
/owasp
WHY: Systematic vulnerability checklist—injection, XSS, CSRF, auth bypass. The Top 10 catches what intuition misses.
/leveson
WHY: STAMP/STPA safety analysis—"Accidents are system failures, not component failures." Check control loops and constraints.
5
Run Tests
/dodds
WHY: Testing Trophy (Integration > Unit > E2E). "Write tests that give confidence." Test behavior, not implementation.
/meszaros
WHY: xUnit Test Patterns—avoid test smells, proper fixtures, test doubles. The patterns prevent flaky, coupled tests.
6
External Validation
Gemini Review
WHY: Different model = different blind spots. Claude has biases; Gemini catches what Claude misses. Architecture and logic review.
Qodana Scan
WHY: Static analysis finds mechanical issues—unused code, code smells, security vulnerabilities. Catches what humans overlook.

If issues found → loop back to Step 3 with specific feedback

7
Commit

All gates passed. Git commit with conventional message. Mark PRD item complete. → Next item or DONE.

Inner² External

$ claude "/ralph-loop PRD.md"
