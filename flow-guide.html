Plan
3 / 6

Plan

Enforce quality before you write a single line.

--plan or /plan
Full planning. Creates .plan.md file, enforces read-only exploration, requires explicit approval. For complex architecture.
> Build the authentication system --plan
> /plan Design the API for payments
--structure-first or /structure-first
Lightweight alternative. Plan inline, get approval, implement. No file created. For simpler features with obvious structure.
> Build a user dashboard --structure-first
> /structure-first Add shopping cart

Why Canon Makes Claude a Better Planner

Kernighan
"Is this clear to someone who didn't write it?"
Pike
"How small can this interface be?"
Linus
"What data structure eliminates special cases?"
Thompson
"Could brute force solve this simpler?"
Dijkstra
"What invariants must always hold?"

"What happens when this fails?"

Canon turns planning into a design review — before code exists.

Build
4 / 6

Build

New features or improving legacy — different flags for different goals.

--build-from-plan or /build-from-plan
New features. Build or resume from .plan.md file. Implements exactly per plan without re-exploring.
> --build-from-plan
> /build-from-plan auth-system.plan.md
--refactor-clean or /refactor-clean
Legacy code. Systematic decomposition with before/after metrics. Breaks down large functions, extracts concerns.
> --refactor-clean src/legacy/BigController.js
> /refactor-clean src/utils/helpers.ts
--test [level] or /test [level]
Write tests alongside code. Levels: unit, integration, e2e, all. Uses Dodds, Meszaros, Feathers + canon.
> Build payment processor --test integration
> /test e2e src/checkout/
--doc-code or /doc-code
Generate documentation using Procida's Diátaxis: tutorials, how-tos, reference, explanation.
> Document the data pipeline --doc-code
> /doc-code src/services/

Build quality in, don't bolt it on.

Flag ↔ Command
--test all chains with prompts · /test all runs standalone

Review

Review

Enforce quality after code is written.

--review-hard or /review-hard
Adversarial self-review. Claude critiques its own work for issues, edge cases, standard violations.
> Build auth flow --structure-first --test all --review-hard
> /review-hard # Review what was just built

The Review Pipeline — For Critical Code

Stage 1

--review-hard

Self-review. Fast, free. Catches consistency issues and standard violations.

Stage 2

Gemini Review

Different model, different biases. Good for architecture review.

Stage 3

Qodana

Static analysis. Security, types, code smells. Deterministic.

Different reviewers catch different problems.
