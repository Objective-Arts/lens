Plan

Enforce quality before you write a single line.

WORKFLOW ORDER
/plan → /structure-first → /build-from-plan → /refactor-clean → /test → /review-hard
/plan
Full planning. Creates .claude/plans/ file, enforces read-only exploration, requires explicit approval. For complex architecture.
> /plan
> /plan auth-system
/structure-first
Design data structures first. Define types, interfaces, and APIs before implementation. For features with clear boundaries.
> /structure-first
> /structure-first UserAuth

Build

New features or improving legacy — workflow skills for different goals.

/build-from-plan
Execute the plan. Implement code from approved plan file. Follows steps exactly without re-exploring.
> /build-from-plan # From most recent plan
> /build-from-plan auth-system # From specific plan
/refactor-clean
Clean up code. Systematic decomposition with before/after structure. Breaks down large functions, extracts concerns.
> /refactor-clean # Recent code
> /refactor-clean src/legacy # Specific path
/test [level]
Write tests. Levels: unit, integration, e2e, or all. Uses Dodds, Meszaros, Feathers + domain canon.
> /test # All levels
> /test unit src/utils # Unit tests for path

Build quality in, don't bolt it on.

Review

Review

Enforce quality after code is written.

/review-hard
Adversarial self-review with optional multi-model validation. Claude critiques its own work, then optionally validates with Gemini and Qodana.
> /review-hard # Review most recent code
> /review-hard src/api # Review specific path
> /review-hard --full # Include Gemini + Qodana

The Review Pipeline — For Critical Code

Stage 1

/review-hard

Self-review. Fast, free. Catches consistency issues and standard violations.

Stage 2

Gemini Review

Different model, different biases. Good for architecture review.

Stage 3

Qodana

Static analysis. Security, types, code smells. Deterministic.

Different reviewers catch different problems.
